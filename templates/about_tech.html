SaaS primer

What is SaaS?
Software licensed by subscription and hosted centrally, rather than sold as a one-time license and installed locally. IaaS provides raw infrastructure, PaaS a platform to build on, SaaS a finished application.
Business model types
Pure subscription, usage-based (pay-as-you-go), freemium-to-paid conversion, and affiliate/partner-led — each implies a different growth and margin profile, which is why pricing_model is a real input feature here.
Why investors like SaaS
Recurring revenue is predictable and compounds — high NDR means a company grows even with zero new sales, which is exactly what the Rule of 40 and NDR components of the health score reward.

NDR / NRRCohort revenue at period end / same cohort at period start. Industry median ≈106%, top-quartile ≥120% (KeyBanc Capital Markets benchmark).

Gross Margin(Revenue - COGS) / Revenue
TAM/SAM/SOMSOM/SAM and SAM/TAM ratios → a market-opportunity tier
Cross-border premiumcross_border_premium_multiplier() — 1.35x cross-border, 1.00x domestic baseline

SaaS Health Score — an authored rubric, not a standard formula

No single industry-standard "SaaS health score" exists, so this is explicitly a weighted scheme built on the metrics above: Rule of 40 (30%) + NDR (30%) + LTV:CAC (20%) + ARR/employee (20%), each scaled 0-100 against its cited benchmark threshold, then blended into bands (Hypergrowth/Efficient, Healthy, Cash-constrained, At-risk). Declared as authored, not scraped from any external scoring system.

Compensation model

Training data

data/generate_dataset.py produces a seeded, synthetic dataset of ~24,500 Indian SaaS employee profiles across ~1,000 synthetic companies — explicitly synthetic, since real payroll data is confidential. Base pay bands, city-tier premiums, and the cross-border premium are calibrated against real 2026 India SaaS compensation ranges (Chennai ~Rs.7.9-8.7 LPA; Freshworks/Zoho-tier Rs.6-12 LPA; funded startups/unicorns Rs.15-30 LPA; cross-border/FAANG-tier Rs.35-60 LPA). Each synthetic company's health score is computed by the exact same saas_metrics.py functions the live calculator uses.

Why quantile gradient boosting over linear regression

{% set lin = metrics.get("Linear Regression (baseline)", {}) %} {% set boost = metrics.get("HistGradientBoostingRegressor (P50, production)", {}) %} Level-based pay bands include real step-function jumps at promotion boundaries — exactly what a linear model can't represent. On held-out data, Linear Regression scores R²={{ "%.2f"|format(lin.get("r2", 0)) }} (MAE ±{{ "%.1f"|format(lin.get("mae_lpa", 0)) }} LPA) versus {{ "%.2f"|format(boost.get("r2", 0)) }} (MAE ±{{ "%.1f"|format(boost.get("mae_lpa", 0)) }} LPA) for a quantile-loss HistGradientBoostingRegressor — a real, measured gap, not an assumed one. 5-fold cross-validation confirms it's stable, not a lucky split (see README). Three separate models (alpha=0.25/0.5/0.75) produce the P25/P50/P75 range; predictions are sorted at serving time to guard against quantile crossing.

CTC breakup & ESOP

ctc_rules.py splits the median prediction per India's Code on Wages (enforced 2026-04-01: Basic+DA ≥50% of CTC), HRA at 50%/40% of Basic for metro/non-metro cities, employer EPF at 12% of Basic, and gratuity accrual at ~4.81% of Basic — the components always sum exactly to the predicted CTC (check an offer against these rules). ESOP is estimated two ways: a paper FMV via a documented, funding-stage-indexed cash:equity table, and a risk-adjusted expected value (liquidity probability × payout multiple, by health band) — explicitly a heuristic, not options pricing, since an illiquid private-company option has no observable strike price or volatility to price one against.

The "real-time" layer — simulated, and labeled as such

A genuinely live integration (Crunchbase/Tracxn funding webhooks, live job-board scraping, a Kafka/Redis pipeline) needs paid API access, always-on infrastructure, and raises scraping ToS concerns this project has neither the budget nor the standing to take on. Rather than fake that connection, market_signals.py runs a background emitter that produces synthetic market events (funding rounds, hiring surges, retention shifts) as small, bounded, decaying adjustments held in memory, streamed to the browser over Server-Sent Events (see the pill in the top bar). It demonstrates the event-driven architecture — state, decay, a live-updating UI — that a real feed would plug into at exactly one function (_random_event()), without claiming a live connection that doesn't exist.

Technology stack

Python & Flask
Python for the modeling stack; Flask for a lightweight server, including a generator-based SSE endpoint for the live-signal feed.
Pandas, NumPy & scikit-learn
Pandas/NumPy for data generation and feature engineering; scikit-learn's HistGradientBoostingRegressor (quantile loss) for the production model — no external boosting library needed.
SHAP
TreeExplainer gives an exact, per-feature contribution for every prediction, aggregated from one-hot-encoded columns back to the original feature.
