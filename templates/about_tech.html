Project background

Methodology & technology

Originally built during a 6-week AI/ML internship (IBM SkillsBuild, supported by Edunet Foundation). This page documents how the model was built and how the application serves it in production.

What the app does

  • Serves real-time salary predictions from a trained regression model.
  • Runs the same preprocessing pipeline used at training time on every request.
  • Generates a downloadable PDF summary of each prediction.
  • Stores nothing — every request is stateless.

Core outcomes

  • Deployed a complete ML web application end-to-end.
  • Benchmarked multiple regressors with R², RMSE, MAE, and k-fold cross-validation.
  • Tuned hyperparameters with GridSearchCV to select the final model.
  • Cleaned and engineered features from the source dataset.

About the training data

Salary Data.csv is 373 rows of Age, Gender, Education Level, Job Title, Years of Experience, and Salary — nothing else. There's no country, city, or currency field, and salaries range from $350 to $250,000 with a mean around $100,577, which puts it in US-market territory. Predictions are shown in USD for that reason: this app doesn't apply any currency conversion, because a currency conversion isn't a labor-market conversion, and presenting a converted figure as region-specific compensation would overstate what the model actually knows.

Technology stack

Each component was chosen for a specific role in the pipeline, from raw data to a served prediction.

Python & Flask

Python for the modeling stack; Flask for a lightweight, predictable web server with full control over routing and templates.

Pandas & NumPy

Pandas' DataFrame handled loading, cleaning, and feature engineering; NumPy backs the underlying numeric operations.

Scikit-learn & SHAP

Scikit-learn for preprocessing (encoding, scaling) and the final Random Forest regressor; SHAP explains each individual prediction.

Model selection

A multi-model comparison was run before settling on a final algorithm.

Models evaluated

  • Linear Regression
  • Random Forest Regressor
  • Gradient-boosted trees (XGBoost)
  • GridSearchCV for hyperparameter tuning
  • K-fold cross-validation for robustness

Why Random Forest

The Random Forest Regressor gave the best balance of accuracy and generalization on the held-out set, and — as a tree ensemble — supports exact, per-prediction explanations via SHAP, which matters as much as raw accuracy for a tool people use to negotiate compensation.

From notebook to application

Two separate phases, deliberately kept apart: research in a notebook, then a small production service that only replays what the notebook proved.

Phase 1 — Research (Jupyter)

Exploration, feature engineering, and model comparison happened in a Jupyter notebook, where iteration is fast and results are visible inline.

Deliverables:

  • A reproducible preprocessing pipeline.
  • The trained, validated Random Forest model.
  • Fitted scaler and label encoders, serialized as .pkl files.

Phase 2 — Serving (Flask)

main.py doesn't train or experiment — it loads the artifacts from phase 1 and replays the exact same transformations on every request:

  • Receive form input from the browser.
  • Load the model and preprocessing objects from disk.
  • Apply identical encoding and scaling to the input.
  • Run inference, then explain it with SHAP before rendering the result.
